ImageKeeper 用来从大量图片中找出完全重复、疑似压缩和内容相近的版本，并把证据整理成便于人工复核的分组。所有分析都在本机完成；软件优先避免误删，不会因为两张图片“看起来很像”就直接删除文件。

> 核心原则：宁可保留一张可疑图片，也不把无法证明的图片当成重复项处理。

## 它是做什么的

ImageKeeper 支持两种整理方式：

- **单目录内部对比**：在一个目录中查找重复、压缩版本和视觉相近的图片。
- **基准目录与对比目录**：指定一个可信的原图库作为基准，再检查一个或多个待整理目录中的图片是否已被基准库覆盖。

一次任务会扫描图片、缓存元数据和特征、召回相似候选、计算相似度并给出保守分类。结果页可以查看组内参考图、候选关系、分辨率、文件大小、感知哈希距离和相似度，再由用户决定是否将低质量副本移入 Windows 系统回收站。

ImageKeeper 不是相册管理器，也不会根据角色名、作品名或文件名自动理解一套组图的语义关系。

## 找差分图小工具

首页的“找差分图”入口会打开独立窗口，适合临时用一张或多张参考图收集和整理相关图片：

1. 第一步添加多张参考图和一个或多个搜索目录，确认后开始查找。
2. 查找过程中原位显示扫描进度；目标目录只扫描一次，再分别与每张参考图进行直接比较。
3. 查找完成后自动进入第二步，在同一张文件表格中按参考图或匹配类型筛选、勾选文件并直接编辑新名称。
4. 需要统一编号时可展开批量命名规则；底部操作栏只处理已勾选文件，并可执行重命名、新建文件夹后移动或复制到其他目录。

重命名支持普通模板和通配符捕获：

- `$name`：原文件名，不含扩展名。
- `$ext`：原扩展名。
- `$ref`：最佳匹配参考图的名称。
- `$n`、`$n:02`、`$n:03`：当前表格顺序及补零形式。
- `$group`：参考图顺序。
- 高级模式中，原名称规则里的每个 `*` 依次对应 `$1` 至 `$9`。

例如 `$ref-$n:02.$ext` 可生成 `三月七-01.png`；高级规则 `*_*.png → $2-$1.png` 可把 `表情_角色.png` 改为 `角色-表情.png`。“按首项快速编号”则以第一行当前名称为基础生成 `_1`、`_2`……，并保留每个文件原本的扩展名。

所有批量操作都会先预览。批次内重复名称、Windows 非法名称和已有不同内容的同名目标会阻止执行；工具不会静默覆盖文件。重命名和移动支持在窗口会话内撤销最近批次，复制不会自动删除已经生成的副本。

## 工作流程

1. **扫描文件**：递归读取支持的图片，记录路径、大小、尺寸、格式和修改时间。
2. **识别完全重复**：计算 BLAKE3 内容哈希；哈希完全相同才属于字节级重复。
3. **召回视觉候选**：计算 64 位感知哈希，以汉明距离筛选可能相似的图片，避免对所有候选执行昂贵计算。
4. **归一化并评分**：两张图片统一到像素数较少图片的完整宽高，使用 Lanczos3 缩小较大图片，再通过 11×11、`sigma=1.5` 的灰度高斯窗口计算标准 SSIM。
5. **保守分类**：综合哈希、相似度、分辨率、文件大小、宽高比和候选冲突，生成唯一结果类型。
6. **人工复核**：在相似图片组中查看证据、调整分组范围并确认低质量候选。
7. **回收与导出**：确认后的文件移入 Windows 系统回收站，可在系统回收站恢复或永久删除；程序保留操作日志并支持导出删除清单和报告。

### 正式任务历史缓存

正式对比任务会把指定分组宽松度下的分组快照和已经完成的组内 SSIM 交叉验证结果写入 SQLite。重新打开历史任务时会优先复用这些结果，不再对全部图片重复执行 pHash 两两分组，也不会重复解码已经完成交叉验证的组。

相似图片分组列表会在每组前显示 SSIM 状态灯：绿色表示已经比对完成并缓存，黄色表示正在比对，红色表示正在排队、尚未比对或等待失败重试；悬浮或聚焦状态灯可以查看具体状态。

打开或切换到某一组时，程序会立即使用 4 路实时计算池优先比对当前组，不需要等待单线程后台队列。当前组完成后，程序会继续使用独立的单线程后台池，依次补算尚未持久化的其他组；同一任务和分组宽松度只会运行一条后台队列。

缓存只属于正式任务，并同时绑定算法配置、分组宽松度、组成员和当前文件指纹。文件发生变化、算法配置升级、分组宽松度改变，或回收/恢复操作改变图片集合时，对应结果会自动失效。升级前已经存在的历史任务会在首次打开时生成一次分组快照，之后即可复用。

“找差分图”和“图片指标测试”不读取正式任务缓存，也不把临时结果写入这些表；两者仍然针对当前文件实时解码和计算。

主流程、组内交叉比较、找差分图和图片指标测试共用同一个标准 SSIM 与 pHash 实现。同一图片对采用相同归一化协议，不再存在低精度和标准模式的数值差异。SSIM 在界面中直接显示 `0–1` 附近的原始值，不转换为百分比。

### 临时图片指标测试

首页的“图片指标测试”会打开独立窗口，用于临时观察多张图片相对一张底图的感知哈希距离和标准 SSIM。选择底图后自动计算，图片解码、pHash 和 SSIM 均受统一的 4 路并行上限约束。

选定标准图后，每张候选图的文件大小右侧会提供“差异高亮”开关。开启后，候选卡片会直接显示使用红色蒙层和黄色轮廓框标记的差异结果，再次点击即可恢复原图。该预览只用于人工观察，不会改变正式任务的分类、保留建议或删除建议。

差异预览会限制源图片像素数量并在计算前后校验文件指纹；超大图片或计算期间被替换的图片会提示重新导入或先缩小后再试。

这个工具不创建正式任务、不写入数据库，也不提供删除建议。窗口关闭后，导入列表和所有计算结果都会清空。

## 如何区别差分图和组图

“差分图”和“组图”不是同一级别的二选一结果：**组图是图片集合，差分图是集合中某张图片与基准候选之间的关系结论。** 一组图片里可以同时包含原图、压缩图和多张差分图。

### 组图：先把视觉相近的图片放在一起

软件对任务中已完成扫描的图片比较 64 位感知哈希。两张图片的汉明距离小于或等于分组范围时会建立连接，再通过并查集生成连通分组：

- 默认分组距离为 `10`，界面可在 `0–24` 之间调整。
- 距离越小，分组越严格；距离越大，召回更多，但误分组的概率也会增加。
- 分组具有传递性：如果 A 接近 B、B 接近 C，三张图片可能属于同组，即使 A 与 C 的距离超过阈值。
- 组内参考图优先选择总像素数更高的图片；像素数相同时，优先选择文件更大的图片。
- “进入同一组”只表示值得一起复核，不证明它们重复，更不代表可以删除。

这里的组图是**视觉相似分组**，不是基于人物、场景或文件命名进行语义聚类。内容明显不同但属于同一套作品的图片，当前版本可能不会被归到同组。

### 差分图：再判断是否存在应该保留的内容变化

`variant`（差分/变体）是对比目录图片相对于基准图片的分类。判定顺序是：

1. BLAKE3 相同，优先判为完全重复，不再判差分。
2. 使用感知哈希从基准目录召回候选，再计算归一化相似度。
3. 多个最佳候选的分数差不超过默认 `0.001` 时，判为“无法确定”，避免随意选择原图。
4. 在默认配置下，最佳相似度达到 `0.75`、低于 `0.995`，并且分辨率完全相同或总像素比例处于 `0.95–1.05` 时，才可能判为差分图。

这类图片通常主体和构图接近，但存在表情、动作、文字、局部元素或其他应保留的变化。差分图默认保留，不进入自动低质量清理建议。

### 压缩图：必须同时满足有方向的低质量条件

“疑似压缩”不能只看文件大小或相似度。当前默认规则要求对比图相对于基准图同时满足：

- 宽度更小；
- 高度更小；
- 总像素数更少；
- 文件大小更小；
- 宽高比相对差异不超过 `0.005`；
- 相似度大于或等于 `0.995`。

同分辨率重编码不会被判为“疑似压缩”。若证据不完整、候选被截断或多个候选冲突，软件会降级为保留或人工确认。

## 结果类型

| 类型 | 含义 | 默认处理 |
| --- | --- | --- |
| `exact_duplicate` | BLAKE3 完全一致的字节级重复 | 可作为清理候选，需确认 |
| `likely_compressed` | 有明确方向的疑似低质量缩放/压缩版本 | 可作为清理候选，需确认 |
| `variant` | 主体相近但存在应保留的内容差异 | 保留并复核 |
| `similar_keep` | 相似，但不满足压缩或差分条件 | 保留 |
| `no_baseline_match` | 未在基准目录找到足够可信的候选 | 保留 |
| `inconclusive` | 候选冲突、截断或证据不足 | 保留并人工确认 |
| `not_evaluated` | 尚未完成必要计算 | 不执行操作 |
| `error` | 文件解码、特征计算或其他步骤失败 | 不执行操作 |

## 技术栈

| 层级 | 技术 | 用途 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | 提供原生窗口、命令调用和文件访问能力 |
| 前端 | Vue 3、TypeScript、Vite 5 | 构建交互界面与开发工具链 |
| UI 与状态 | Element Plus、Pinia、Vue Router | 组件、任务状态和页面路由 |

| 图片特征 | BLAKE3、64 位感知哈希 | 精确重复识别与视觉候选召回 |
| 输出 | `csv`、文本与 HTML 报告 | 导出清理清单和分析记录 |

## 支持格式

当前默认配置扫描：

- JPG / JPEG
- PNG
- WebP
- BMP
- GIF（读取第一帧）

损坏、无法解码或未启用的格式会记录为未评估或错误，不会变成清理操作。

## 安全边界

- 基准目录只作为可信参考，不提供删除入口。
- 感知哈希分组只是候选召回，不能单独作为删除依据。
- 差分图、同分辨率变体和无法确定的结果默认保留。
- 移入 Windows 系统回收站前会重新检查路径、文件状态和 BLAKE3 指纹，防止扫描后文件被替换。
- 删除动作只作用于对比目录图片，并记录操作日志。
- 单文件失败不会影响无关图片；关键任务或数据库失败会停止流程并保持保守结果。

## 开发与运行

### 环境要求

- Node.js 与 npm
- Rust stable toolchain
- [Tauri 2 对应平台依赖](https://v2.tauri.app/start/prerequisites/)
- Windows 开发环境需要 WebView2；较新的 Windows 版本通常已预装

### 安装依赖

```bash
npm install
```

### 启动桌面开发模式

```bash
npm run tauri:dev
```

### 验证前端构建

```bash
npm run build
```

### 运行 Rust 测试

```bash
cargo test --manifest-path src-tauri/Cargo.toml
```

### 从矢量源重新生成应用图标

```bash
npx tauri icon assets/imagekeeper-logo.svg
```

生成结果写入 `src-tauri/icons/`。请勿直接手工修改生成后的 PNG、ICO 或 ICNS 文件。

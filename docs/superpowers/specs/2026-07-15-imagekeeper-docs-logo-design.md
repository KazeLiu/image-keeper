# ImageKeeper 文档与 Logo 重设计说明

## 目标

让首次接触项目的人能从 README 快速理解 ImageKeeper 的用途、处理流程、技术组成，以及“差分图”和“组图”的关系；同时用一套可缩放、可重复生成的应用图标替换当前临时图标。

## README 设计

README 以实际代码为准，按“产品定位 → 使用流程 → 差分图与组图 → 技术栈 → 安全边界 → 开发运行”的顺序重写，删除无法由当前实现证明的性能与完成度宣传。

产品定位为本地桌面图片对比与整理工具。用户选择一个基准目录和一个或多个对比目录，软件扫描图片并给出重复、疑似压缩、差分/变体、相似但保留、无匹配或无法确定等结果；自动分析不等于自动删除。

### 差分图与组图

这两个概念处于不同层级，不是互斥分类：

- “组图”是浏览与复核容器。当前实现对任务内已扫描图片计算 64 位 pHash，以可调汉明距离（默认 10，可选 0–24）连接相近图片，再用并查集形成连通分组。连接具有传递性，因此同组首尾图片不保证彼此都低于阈值。组内参考图优先选择像素数更高、文件更大的图片。
- “差分图”对应代码中的 `variant`，是对比目录中的单张图片相对于基准候选得到的分析结论。BLAKE3 完全相同会先判为精确重复；非精确候选经过 pHash 召回和归一化相似度计算。默认情况下，相似度达到 0.75、低于 0.995，且分辨率相同或总像素数接近（0.95–1.05）时，才可能判为差分/变体；候选冲突会转为“无法确定”。
- 疑似压缩要求方向明确：对比图宽、高、总像素数和文件大小都小于基准图，宽高比在容差内，且相似度达到默认 0.995。差分图与其他应保留的相似图默认不进入自动清理建议。
- 组内交叉复核只用于把低质量候选挂到更可能的原图下，不把“同组”直接等同于“可删除”。

README 会明确当前相似度实现是灰度归一化后的像素差评分，而不是对外宣称未经实现验证的完整窗口 SSIM。

## Logo 设计

采用“守护取景框”方案：

- 外轮廓为圆角方形，适配 Windows 应用图标和小尺寸任务栏显示。
- 两张错位图片卡片表示图库、相似分组与版本对比。
- 前景卡片中的盾牌勾形负空间表达“保护原图、谨慎清理”。
- 主色使用深靛蓝 `#312E81` 到亮青蓝 `#22D3EE` 的渐变，前景使用近白色 `#F8FAFC`；轮廓在 16px 下仍需可辨。
- 不使用文字、Emoji、细线或写实相机，以避免跨平台字体差异和缩小后的视觉噪声。

仓库保留 SVG 矢量源文件，并通过 Tauri 图标命令生成 Windows ICO、PNG 和其他平台标准尺寸。README 顶部展示矢量 Logo。

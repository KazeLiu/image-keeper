# 找差分图小工具设计

日期：2026-07-15  
状态：待用户复核

## 1. 目标

为 ImageKeeper 增加一个独立的“找差分图”小工具。用户可以一次加入多张参考图和多个搜索目录，程序只扫描目录一次，随后为每张参考图查找完全相同、压缩/重编码、差分和视觉相关组图。用户既可以按参考图查看结果，也可以在汇总视图中统一重命名、移动或复制命中的文件。

本工具面向临时整理，不复用现有“新建任务/加载任务”的任务入口和历史任务界面；但复用现有图片解码、BLAKE3、pHash、归一化相似度与保守分类能力。

首版“组图”指能够与参考图建立直接视觉相似关系的图片。仅仅属于同一角色或同一作品、但动作和构图完全不同的语义组图不在首版保证范围内。

## 2. 入口与窗口

- 在首页“选择新建任务”和“加载任务”两张大卡片下方增加一张尺寸更小的工具卡片。
- 卡片标题为“找差分图”，说明为“用多张参考图从多个目录查找差分、重复与相关组图”。
- 点击卡片后创建独立 Tauri 窗口，主窗口保持原状态。
- 工具窗口使用独立路由 `/difference-finder`，建议初始尺寸 `1280 × 820`，最小尺寸 `980 × 680`。
- 重复点击入口时，如果工具窗口已经存在，则聚焦已有窗口，不重复创建。
- 关闭工具窗口会取消仍在运行的会话级任务并释放内存缓存，不改变主工作台状态。

## 3. 总体交互流程

1. 加入一张或多张参考图，支持文件选择和拖放。
2. 加入一个或多个搜索目录，默认递归扫描子目录，并去除重复或相互重叠的等价路径。
3. 点击“开始查找”。程序扫描目标目录一次，缓存目标图片元数据和特征，再依次匹配全部参考图。
4. 顶部参考图条展示每张图的状态和命中数。点击参考图只筛选结果，不重新扫描或重新计算。
5. “全部结果”视图汇总所有参考图的命中。相同规范化路径只保留一条操作记录，并展示它命中的全部参考图标签和最佳匹配证据。
6. 用户勾选结果，进入整理表，通过拖拽排序、逐行编辑或批量规则生成新名称。
7. 用户预览并执行重命名、创建文件夹后移动、或复制到指定目录。
8. 工具汇总成功、跳过、冲突和失败项目；重命名与移动支持撤销最近一次完整批次。

新增参考图时复用目标扫描缓存，只计算新增参考图与已有目标图片的关系。新增搜索目录时只扫描新增目录，再补算所有参考图与新增图片的关系。

## 4. 页面布局与状态

### 4.1 输入区

- 参考图区域：横向缩略图列表、添加、移除、清空、启用/停用。
- 搜索目录区域：目录路径、递归状态、图片数量、移除按钮。
- 查找按钮：没有有效参考图或搜索目录时禁用。
- 进度：区分扫描、特征计算、候选召回、精细评分和汇总阶段，并可取消。

### 4.2 结果区

- 筛选项：全部结果、单张参考图、结果分类、来源目录、仅已勾选。
- 结果分类：完全相同、压缩/重编码、差分图、相关组图、弱相关候选。
- 每个结果显示缩略图、文件名、完整路径、来源目录、分辨率、格式、文件大小、命中参考图、pHash 距离、精细相似度和分类说明。
- 点击缩略图打开大图对比；可在参考图和候选图之间切换或并排查看。
- 同一文件命中多张参考图时，按最佳关系排序分类，并保留其他命中关系用于展示，不产生重复文件操作。

### 4.3 整理表

整理表优先使用专用 div/grid 实现，以便稳定支持拖拽、缩略图、输入框和行级状态。每行包含：

1. 勾选框。
2. 拖拽手柄和当前顺序。
3. 图片缩略图。
4. 原文件名，只读。
5. 新文件名输入框，默认等于原文件名。
6. 命中参考图与分类。
7. 校验状态。

拖拽后的顺序是所有顺序变量和快速重命名的唯一编号来源。单行输入框允许直接覆盖生成结果；再次应用批量规则时，只更新当前勾选行，并明确提示是否覆盖手工编辑过的名称。

## 5. 重命名规则

### 5.1 基础原则

- 批量规则只生成预览，不直接修改文件。
- 默认保留原扩展名；重命名不转换图片编码或格式。
- 规则输入框旁提供可点击的变量按钮、简短说明和实时示例。
- 输入变化后立即刷新整理表中的新名称和冲突状态。
- 用户仍可在行内修改任意生成结果。

### 5.2 简单模板模式

默认向普通用户展示一个“新名称格式”输入框，支持：

| 变量 | 含义 | 示例输出 |
| --- | --- | --- |
| `$name` | 原文件名，不含扩展名 | `角色_表情` |
| `$ext` | 原扩展名，不含点 | `png` |
| `$n` | 当前拖拽顺序，从 1 开始 | `1` |
| `$n:02` | 两位补零顺序 | `01` |
| `$n:03` | 三位补零顺序 | `001` |
| `$ref` | 最佳匹配参考图的文件名，不含扩展名 | `三月七` |
| `$group` | 当前参考图在参考图条中的顺序 | `2` |

示例一，按参考图名称统一编号：

```text
格式：$ref-$n:02.$ext
结果：三月七-01.png、三月七-02.jpg、三月七-03.webp
```

示例二，在原名称前添加前缀：

```text
格式：收藏-$name.$ext
原名：立绘_微笑.png
结果：收藏-立绘_微笑.png
```

示例三，保留原名并追加三位序号：

```text
格式：$name-$n:03.$ext
结果：立绘-001.png、差分-002.png、背景-003.jpg
```

### 5.3 高级捕获模式

高级区域包含“原名称匹配”和“新名称格式”两个输入框。默认采用容易理解的通配符语法：原名称匹配中的每个 `*` 从左到右生成 `$1` 至 `$9`，新名称格式通过这些变量复用捕获内容。

示例一，交换下划线两侧内容：

```text
原名称匹配：*_*.png
新名称格式：$2-$1.png
原名：表情_角色.png
结果：角色-表情.png
```

示例二，保留角色和编号并调整结构：

```text
原名称匹配：*-*-*.jpg
新名称格式：$1_差分_$3.jpg
原名：流萤-表情-07.jpg
结果：流萤_差分_07.jpg
```

示例三，在捕获结果后按拖拽顺序重新编号：

```text
原名称匹配：*_*.webp
新名称格式：$1-$n:02.$ext
原名：卡芙卡_旧编号.webp
结果：卡芙卡-01.webp
```

若某一行不能匹配原名称规则，该行保持原名称并标记“规则未匹配”，不会生成空文件名。首版不要求用户书写正则表达式；正则可作为后续高级能力，避免同时暴露多套捕获语法。

### 5.4 快速重命名

提供独立按钮“按首项快速编号”。点击后：

1. 读取当前整理表第一行的“新文件名”；如果第一行尚未编辑，则等同于原文件名。
2. 去除第一行扩展名，作为基础名称。
3. 按当前拖拽顺序生成 `基础名称_1`、`基础名称_2`……。
4. 每个文件保留自己的原扩展名。

示例：第一行当前名称为 `三月七.png`，三行分别为 PNG、JPG、WebP，则结果为：

```text
三月七_1.png
三月七_2.jpg
三月七_3.webp
```

快速重命名同样只生成预览，可以继续逐行修改。第一行也带 `_1`，避免第一行和后续结果采用不同命名结构。按钮旁明确说明“以第一行名称为基础，按当前拖拽顺序追加 `_1`、`_2`……”。

## 6. 文件名校验与冲突处理

生成预览时同时检查：

- 选中行之间是否产生相同目标路径。
- 目标目录中是否已有同名文件。
- Windows 大小写不敏感冲突。
- Windows 保留名称、尾随空格/句点、非法字符和路径长度。
- A 改成 B、B 改成 A，以及多文件循环换名。
- 源文件在扫描后是否被移动、删除或修改。

状态约定：规则错误和批次内重复为红色，禁止执行；目标目录已有不同内容的同名文件为黄色冲突，默认跳过；目标中已有 BLAKE3 相同内容时标记“相同内容已存在”。不提供静默覆盖。

执行批量重命名时，先把参与改名的文件改为同目录下的唯一临时名称，再改为最终名称，正确处理交换名称和循环名称。任一步失败时尽量回滚该批次，并把不能自动恢复的项目标记为“需要人工处理”。

## 7. 移动与复制

### 7.1 创建文件夹并移动

- 用户选择目标父目录并输入新文件夹名。
- 工具预览最终目录和每个目标路径。
- 目录已存在时允许复用，不重复创建。
- 默认不覆盖目标中的不同内容同名文件。
- 移动成功后更新当前结果路径；失败项目保留原路径并单独报告。

### 7.2 快速复制

- 用户选择目标目录，工具记住本工具窗口最近一次使用的目标路径。
- 复制保留源文件，默认不覆盖。
- 目标存在相同 BLAKE3 内容时跳过并显示“相同内容已存在”。
- 目标存在同名但内容不同的文件时，默认标记冲突；用户可选择为冲突项自动追加 `_1`、`_2`，但必须重新预览后执行。

## 8. 方案取舍与匹配数据流

评估过三种实现方向：

1. **复用现有多目录任务**：把参考图包装成临时基准目录。改动表面较少，但多张参考图会造成临时目录、重复目标扫描、结果语义错位和无意义的历史任务，不采用。
2. **独立工具工作流，复用底层算法**：目标目录只扫描一次，参考图与目标特征形成多对多关系，界面再按参考图筛选和汇总。这最符合小工具定位，也是首版采用的方案。
3. **引入语义图片模型**：可以召回构图差异很大的同角色或同作品图片，但会增加模型体积、初始化耗时和误报解释成本。保留为未来可选的“宽松语义搜索”，不进入首版。

采用“独立工具工作流 + 复用底层算法”的方案：

1. 规范化并去重参考图和搜索目录路径。
2. 扫描搜索目录，提取文件元数据、BLAKE3 和 pHash。
3. 为参考图提取相同版本的特征。
4. BLAKE3 先识别完全相同内容。
5. pHash 负责召回候选，精细相似度负责排序和分类。
6. 每个候选必须直接与参考图建立关系，不通过传递分组无限扩张。
7. 按规范化文件路径汇总跨参考图命中，并保留全部关系。
8. 前端基于关系筛选结果，文件操作层只接收去重后的文件计划。

不直接把每张参考图伪装成现有“基准目录”，因为这会制造临时目录、重复扫描目标和不必要的历史任务。后端应抽出可复用的单图特征与候选评分服务，由现有工作流和新工具分别调用。

首版继续使用当前保守的 pHash 与归一化像素差评分，不增加大型语义模型依赖。语义组图检索可在未来作为明确标注的宽松模式加入。

## 9. 模块边界

前端建议新增：

- `DifferenceFinderView.vue`：独立窗口页面与流程编排。
- `ReferenceImageStrip.vue`：参考图管理和筛选。
- `DifferenceSearchSetup.vue`：目录与搜索控制。
- `DifferenceResultList.vue`：结果浏览与选择。
- `BatchRenameGrid.vue`：拖拽排序、名称输入、规则预览和冲突状态。
- `RenameRuleHelp.vue`：变量说明与示例。
- `differenceFinderStore.ts`：会话、进度、结果和整理计划状态。
- `differenceFinder.ts`：Tauri 命令封装和前端类型边界。

后端建议新增：

- `commands/difference_finder.rs`：会话、搜索、取消、预检和文件操作命令。
- `core/difference_finder/`：参考图中心匹配、结果汇总与缓存。
- `core/file_operations/`：重命名、移动、复制的计划验证、执行与回滚。
- 独立文件操作批次与明细记录，避免扩展现有仅面向回收站的 `operation_logs` 枚举和外键语义。

页面只能提交“计划”；路径合法性、冲突检查、扫描后文件一致性和最终执行必须由 Rust 后端完成。

## 10. 会话与持久化

- 找差分图会话不出现在现有“加载任务”列表。
- 工具窗口生命周期内保留扫描和匹配缓存。
- 关闭窗口后无需恢复未完成的搜索会话。
- 已执行的文件操作批次写入独立日志，至少记录源路径、目标路径、执行前 BLAKE3、大小、修改时间、结果和错误。
- 最近一次成功的重命名或移动批次允许从工具窗口撤销；复制不自动删除目标副本，只提供操作明细，避免把用户后来修改过的副本误删。

## 11. 错误处理

- 单张参考图损坏：只标记该参考图失败，其余参考图继续。
- 单个搜索文件损坏：记录错误并继续扫描。
- 搜索目录无权限或消失：显示目录级错误，不伪造空结果。
- 用户取消：停止后续调度，保留已经完成的可查看结果，但禁止在仍有未完成预检时执行文件操作。
- 文件操作前重新读取源文件状态并计算必要校验；状态变化则标记过期并跳过。
- 单项文件操作失败不阻断无关项，批次结束后统一汇总。

## 12. 验证与测试

### Rust 单元与集成测试

- 多参考图复用一次目录扫描。
- 同一候选命中多张参考图时只产生一个汇总文件项。
- 参考图中心匹配不会引入仅通过传递关系相似的图片。
- 模板变量、补零编号、通配符捕获和未匹配规则。
- 快速重命名严格使用第一行名称和当前拖拽顺序。
- Windows 大小写冲突、非法名称、已存在目标和同内容目标。
- 交换名称、三文件循环名称、部分失败回滚。
- 移动、复制的执行前状态校验和批次结果。

### 前端测试与人工验收

- 首页小卡片打开并复用独立窗口。
- 多图拖入、目录添加、取消搜索和增量添加参考图。
- 切换参考图只筛选结果，不重复搜索。
- 拖拽顺序立即更新 `$n` 和快速重命名预览。
- 行内手工名称、批量规则和手工覆盖提示行为一致。
- 规则帮助中的每个示例与实际预览结果一致。
- 冲突行视觉状态明确，未解决的红色错误不能执行。
- 重命名、移动、复制完成后路径和状态正确刷新。

完成标准是：用户能在独立窗口中用多张参考图完成一次多目录检索，在汇总结果中安全生成并预览批量名称，通过拖拽控制编号，执行无静默覆盖的重命名、移动或复制，并能清楚看到每个文件的最终结果。
